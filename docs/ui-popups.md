# ポップの出し方と、開く・閉じる順序

2026-10-30 に、実機で「設定のボタンが反応しない」「戻ると画面が固まる」「チュートリアルで何も押せない」が起きたため、作りを改めた。

## 原因
ネイティブの `Modal` を、入れ子にしていた（設定 → カテゴリ → 確認、規約・クレジット）。iOS では、すでに別の画面を出している `Modal` から、さらに別の画面を出す操作が成り立たない。閉じている最中に、別の `Modal` や `Alert` を出しても、画面が出ないまま、触れない層が残る。Web では起きないので、ブラウザの確認では見つからなかった。

## いまの作り
- アプリの中で `Modal` は使わない（無効にしてある「世界」の画面を除く）。
- ポップは、アプリの一番外側の `OverlayHost` に、**開いた順に下から上へ**重ねる（`src/ui/overlayStore.ts`、`src/ui/Overlay.tsx`）。
- `Popup`、確認（`useConfirm`）、年齢、誕生日、ひらく演出、迎えたときのカード、カメラは、すべてこの仕組みを使う。

## 順序のきまり
1. 開いた順に重ねる。いちばん上のポップだけが触れる（後ろは、上のポップの暗幕が覆う）。
2. 同じポップの内容が変わっても、重なる順は変わらない。
3. 閉じるのは、そのポップだけ。閉じた直後に、別のポップを開いてよい（確認を閉じて、すぐに結果を出す、など）。
4. Android の戻るボタンは、いちばん上のポップだけを閉じる。
5. 短い案内（`notice`）は、OS の `Alert`。ポップの重なりとは別の層で、いちばん手前に出る。

## 新しくポップを足すとき
- `Modal` を直接使わない。`Popup`（枠つき）か `Overlay`（枠なし）を使う。
- 確認は `useConfirm()`。取り消せない操作は、必ず確認を通す。
- ポップの中で、さらにポップを開いてよい。入れ子の扱いは要らない。
