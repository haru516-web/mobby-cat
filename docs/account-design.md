# アカウント・購入・クラウドセーブ（アプリ側の設計）

2026-10-28。サーバー側は `server/README.md`。ここは、アプリ側が何を持ち、どう動くか。

## 方針

- **遊ぶだけなら、アカウントは作らない。** 記録は端末の中（AsyncStorage）。サーバーへは何も送らない。起動しただけでは、通信しない。
- **Apple 連携か購入のときに、はじめてアカウントを作る**（ランダムな番号の匿名アカウント）。
- **購入は、匿名のアカウントのままでできる**（2026-10-29 変更。購入の前の登録を求めると、ガイドライン 5.1.1 で指摘されうるため）。Apple 連携は任意で、購入のあとに案内する。連携していれば、機種変更でも、購入したものと記録を戻せる。
- **無料で得た分は端末内、買った分はサーバーが正しい値を持つ**（`game-design.md` 16.）。

## 持つもの

| 置き場所 | 中身 |
|---|---|
| Keychain（`expo-secure-store`） | アカウントの番号と鍵。この端末だけ（`THIS_DEVICE_ONLY`）。入れ直しても残ることが多い。Web（開発用）は AsyncStorage |
| AsyncStorage `mobby-cat/state/v1` | ゲームの記録（従来どおり）。`paid` に、買った分の残高の**写し**を持つ（表示と、使う前の確認用） |
| AsyncStorage `mobby-cat/cloud/v1` | クラウドに預けた記録の、版・指紋・時刻 |
| サーバー | 買った分の残高、購入の記録、またたびパス、年齢区分、Apple 連携、預けた記録 |

## 画面と流れ

**購入**（ショップ）：アカウントがあるか → Apple 連携済みか（なければ「Appleでサインイン」） → 年齢の区分（なければ選ぶ） → 今月の上限 → 購入シート（`appAccountToken` はアカウントの番号） → サーバーが検証して残高に足す → 取引を終える。途中で止まっても、取引は終わらず残り、次の起動で `settle()` が仕上げる。

**使う**（お迎え券・またたび）：端末内の無料分から先に使い、足りない分をサーバーの残高から引く（`requestId` つき。通信が切れて再送しても二重に引かれない）。通信できないときは、何も引かれず、「お迎えできませんでした」と出る。

**またたびパス**：加入しているかは、サーバーの答え（`/plan`）。毎月のお迎え券（8枚）も、サーバーが購入の更新のたびに残高へ足す（端末内では足さない）。加入した日のうちから、候補が6匹になる。

**クラウドセーブ**（Apple 連携後）：記録が変わって 30 秒たつと預ける（前の預けから 60 秒はあける）。アプリを閉じるときは、待たずに預ける。サーバーは版が合うときだけ上書きを受けるので、古い端末が新しい記録を消すことはない。食い違ったときは、この端末が空なら、そのままクラウドの記録を使い、そうでなければ、設定の「アカウント」で、どちらを使うか選んでもらう。

**機種変更・入れ直し**：新しい端末のオープニング後の相棒選びの画面と、設定の「アカウント」に、「記録を引き継ぐ（Appleでサインイン）」がある。Keychain が残っていて、記録が空の端末は、起動時に自動で戻す。

**アカウントの削除**（設定 → アカウント）：サーバーが Apple のトークンを取り消してから、サーバーの記録を削除し、端末の記録も消す。サーバーが取り消せなかったら、削除されない（やり直せる）。

## つながらない・鍵が合わないとき

- つながらない：前回の写しのまま。購入と使う操作だけが、できないと伝える。
- 401（別の端末が引き継いだ、またはアカウントが無い）：鍵を勝手に捨てない。設定の「アカウント」に案内を出し、「Appleでサインインし直す」か「新しく始める」を選んでもらう。

## 決めていないこと・今回やっていないこと

- またたび単品の商品（価格が未決定。ショップでは「準備中」）。
- チュートリアルの後に、Apple 連携をやさしくすすめる画面（今は、購入の前の必須と、設定のみ）。
- 起動時の App Store Server API による購入状態の再照合（通知の取りこぼし対策）。
- 引き継ぎコード（有効期限つき・1回限り）。
- 実機（TestFlight・サンドボックス）での検証。Web では、購入・Apple サインインは動かない。
