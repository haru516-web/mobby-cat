# アカウント・購入・クラウドセーブ（アプリ側の設計）

2026-10-30 更新。サーバー側は `server/README.md`。ここは、アプリ側が何を持ち、どう動くか。

## 方針

- **遊ぶだけなら、アカウントは作らない。** 記録は端末の中（AsyncStorage）。ゲーム記録をクラウドへ預けるのはApple連携後だけです。アカウントがなくても時計の補正・天気などの機能では通信します。既存アカウントがある場合は、起動・復帰時に購入や残高も確かめます。
- **Apple 連携か購入のときに、はじめてアカウントを作る**（ランダムな番号の匿名アカウント）。
- **購入は、匿名のアカウントのままでできる**（2026-10-29 変更。購入の前の登録を求めると、ガイドライン 5.1.1 で指摘されうるため）。Apple 連携は任意で、購入のあとに案内する。連携していれば、機種変更でも、購入したものと記録を戻せる。
- **無料で得た分は端末内、買った分はサーバーが正しい値を持つ**（`game-design.md` 16.）。

## 持つもの

| 置き場所 | 中身 |
|---|---|
| Keychain（`expo-secure-store`） | アカウントの番号と鍵。この端末だけ（`THIS_DEVICE_ONLY`）。入れ直しても残ることが多い。Web（開発用）は AsyncStorage |
| AsyncStorage `mobby-cat/state/v1` | ゲームの記録（従来どおり）。`paid` に、買った分の残高の**写し**を持つ（表示と、使う前の確認用） |
| AsyncStorage `mobby-cat/cloud/v1` | クラウドに預けた記録の、版・指紋・時刻 |
| サーバー | 買った分の残高、購入の記録、またたびパス、年齢区分、Apple 連携、預けた記録 |

## 画面と流れ

**購入**（ショップ）：アカウントがあるか（なければ匿名で作成） → 年齢の区分（なければ選ぶ） → 今月の上限 → 購入シート（`appAccountToken` はアカウントの番号） → サーバーが検証して残高に足す → 取引を終える。途中で止まっても、取引は終わらず残り、次の起動で `settle()` が仕上げる。

**使う**（お迎え券・またたび）：端末内の無料分から先に使い、足りない分をサーバーの残高から引く（`requestId` つき。通信が切れて再送しても二重に引かれない）。買った分を使う前に、操作ID・対象猫・操作前の日の記録を端末へ保存します。通信できないときは、引かれたか不明なのでジャーナルを残し、同じIDで再確認します。成功後の適用も保存されるまで、次の消費・クラウド置換・リセットを止めます。

**またたびパス**：加入しているかは、サーバーの答え（`/plan`）。毎月のお迎え券（8枚）も、サーバーが購入の更新のたびに残高へ足す（端末内では足さない）。加入した日のうちから、ひらける上限が6匹になります（条件を満たした候補が6匹未満の日は、その数まで）。

**クラウドセーブ**（Apple 連携後）：記録が変わって 30 秒たつと預ける（前の預けから 60 秒はあける）。アプリを閉じるときは、待たずに預ける。サーバーは版が合うときだけ上書きを受けるので、古い端末が新しい記録を消すことはない。食い違ったときは、この端末が空なら、そのままクラウドの記録を使い、そうでなければ、設定の「アカウント」で、どちらを使うか選んでもらう。

クラウドへ預ける出会い候補は、補正時計の出会いの日を含む直近3日だけです。理由文・お知らせ本文・端末の生の観測値は預けず、誕生日の猫の初入手日は年始へ丸めます。ローカルの日履歴は90件と復旧中の対象日までで、所持猫・累計は残します。

**機種変更・入れ直し**：新しい端末のオープニング後の相棒選びの画面と、設定の「アカウント」に、「記録を引き継ぐ（Appleでサインイン）」がある。Keychain が残っていて、記録が空の端末は、起動時に自動で戻す。

**アカウントの削除**（設定 → アカウント）：サーバーが Apple のトークンを取り消してから、サーバーの記録を削除し、端末の記録も消す。サーバーが取り消せなかったら、削除されない（やり直せる）。

## つながらない・鍵が合わないとき

- つながらない：前回の写しのまま。購入と使う操作だけが、できないと伝える。
- 401（別の端末が引き継いだ、またはアカウントが無い）：鍵を勝手に捨てない。設定の「アカウント」に案内を出し、「Appleでサインインし直す」か「新しく始める」を選んでもらう。

## 復元と残る検証

- またたびは5個セット。単品は提供しません。Apple連携は購入後と設定で任意に案内します。
- 匿名購入の引継ぎは、ショップで「購入を復元」を押したときだけです。Apple未連携・有料残高ゼロ・パスなしのアカウントか、アカウントのない端末に限ります。期限内サブスクの証明と旧端末で発行した独立した引継ぎコードを使い、前の端末の鍵を失効させます。コードは30日有効で、新しい1台の鍵にだけ使用できます。通信応答が失われても、その端末に保存済みの同じ鍵なら再送できます。
- 起動時の App Store Server API による購入状態の再照合（通知の取りこぼし対策）。
- 引き継ぎコード（有効期限つき・1回限り）。
- 実機（TestFlight・サンドボックス）での検証。Web では、購入・Apple サインインは動かない。

## 引継ぎコード（同日追補・こちらが現行）

運営者の指定で、購入証明だけの匿名復元を廃止し、独立した引継ぎコードを追加しました。旧端末の設定→アカウントで発行・保管し、新端末のショップで入力します。30日有効、再発行すると前のコードは無効です。Apple連携済みはAppleで引き継ぎます。匿名のゲーム記録は移りません。新端末で確実に保存済みの乱数鍵を使って回復するため、通信応答喪失時は同じコードと同じ新しい鍵で再送できます。同じ購入日時・以前の署名を一律に拒否する前の方式は使いません。
