# 猫モビー コレクションゲーム 企画・設計書

- 対象：iOSアプリ
- 文書種別：企画・プロダクト仕様の統合ドラフト
- 更新日：2026-10-24
- 状態：コンセプト・基本収集方式は合意方向。価格・確率・技術構成などは検討値。

## 1. コンセプト

**日常生活と世界中のユーザーの活動によって猫モビーと出会い、毎日好きな猫を選んで集めるコレクションゲーム。**

アプリを長時間操作しなくても、歩数・スマホの状態・暦・天文現象・既存コレクション・世界全体の活動などが出会いに反映される。SNSでの発見報告には情報価値があり、猫の入手条件は原則すべてのユーザーに共通する。世界を旅する特別な猫に出会う体験もある。

### 基本原則
1. 主役は**猫モビーの収集**。育成・戦闘・複雑な操作は前提にしない。
2. 原則、毎日20:00（利用者のローカル時刻を想定）にその日の出会いを通知する。通知を許可しなくてもアプリ内から利用可能。
3. 原則**3匹の候補から好きな1匹を無料で迎える**。
4. 欲しい猫が複数いれば、**お迎え券**で追加獲得できる。
5. **またたび**は出会いの候補数を増やすアイテムであり、所有枠の拡張とは別。
6. 猫の特殊出現条件は**全ユーザー共通**。情報共有・攻略・SNSでの考察を促す。
7. 無課金でも継続して猫を収集でき、レア猫との出会い自体を課金専用にしない。
8. 旅猫や世界共通報酬の社会的価値・希少性を、直接販売で損なわない。

## 2. 猫モビーのビジュアルと素材

- 参考画像の方向性：ふわふわした毛並み、丸い猫の体、猫種ごとの顔や毛色。
- 維持するモビーの識別要素：**片目がカメラレンズ、胸元の十字キー、丸ボタン2つ**。
- 猫種の参考：ベンガル、バーマン、ボンベイ、ブリティッシュショートヘア、バーミーズ、コーニッシュレックス、デボンレックス、エジプシャンマウ、スコティッシュフォールド等。
- 大量量産は**正面向き透過PNG + 共通アニメーション**を基本とし、必要に応じて耳・しっぽ・目などをパーツ分離。
- 共通モーション例：上下に揺れる、呼吸、まばたき、跳ねる、傾く、タップ反応、睡眠、喜ぶ、怒る。
- 簡易的な画像移動・拡縮・回転・変形はコードで可能。自然な横向き・後ろ向きや本格3D ARには追加素材が必要。
- 多数同時表示する場合は画質・メモリ・描画負荷を計測する。

## 3. 中核の収集ループ

### 3.1 日次の出会い

1. その日の利用者の条件（日付、曜日、月齢、歩数、バッテリー状態、所持猫など）を記録・判定。
2. 所定時刻（案：20:00）に「今日のあなたは3匹の猫モビーと出会いました」と通知。
3. アプリで候補一覧を表示。**3匹から1匹を無料でお迎え**。
4. 残りの候補は任意で**お迎え券**を使用し、1匹ずつ追加獲得できる（2匹でも全匹でもよい）。
5. 迎えた猫はコレクション図鑑に登録。出会った日時・条件・初入手日を記録する。
6. 選ばなかった猫については、見返せる履歴・救済機会を検討する。

### 3.2 特殊条件との統合

- 全ユーザー共通の条件を満たすと、対応する猫がその日の候補に含まれる。
- 攻略投稿に意味を持たせるため、条件が成立したら**原則、確定で候補に現れる**ことを基本に検討。
- 同時に多数の条件が成立して候補枠を超えた場合の扱いは未決定。推奨：条件達成猫の候補保証、別枠表示、または翌日繰越。
- 異なる条件で現れた複数の猫から1匹選ぶ葛藤が、追加お迎え券の自然な購入動機となる。
- スマホの状態など、終了中の取得が保証できないデータは、アプリ起動時や許諾されたデータ取得時に判定する。
- 通知を受け取れない・20:00に開けない人にも救済期間を設ける（翌日までなど、要決定）。

### 3.3 重複

- 同じ種類の猫を複数所有可能にする案。
- 重複の用途：友達との交換、所持数による特殊猫の出現、一定数で未所持猫に交換等。
- 重複だけが続くことによる離脱を防ぎ、一定の無料進捗保証を設ける。
- 同一猫種でも訪問日・出現条件などの思い出記録を保存可能にする。

## 4. 課金・マネタイズ

### 4.1 中核となる2アイテム

**お迎え券**
- 今日出会った候補のうち、無料獲得の1匹に加えて好きな猫を1匹確実に獲得。
- 候補に現れた猫を対象とし、購入後の結果にランダム性を持たせない。
- 「1匹追加で迎える」「2匹追加で迎える」といった購入導線を設ける。
- 原則、レア度別の券を複雑に分けない。

**またたび**
- その日の候補猫を増やす消費型アイテム。
- 仮構成：通常3匹、少量で4匹、中量で5匹、大量で6匹。
- またたびは**選択肢を増やす**が、無料で迎えられる猫は基本1匹のまま。
- 種類別・期間別で候補の抽選確率が変わる場合は透明に提示する。
- 有料消費アイテムは予告なしに失効させない。期限付きの場合は購入前に明示・規約整合を確認。

### 4.2 継続課金：またたびパス

- 月額課金で毎日の候補数が増える（例：3匹→6匹）。
- **都度買いの消費型またたびが自動的に消える**設計ではなく、加入中に毎日追加候補が付与される継続特典として扱う。
- 加入者向けに月数枚のお迎え券を含める案を検討（出会う数だけ増えても選べない不満への対策）。
- 解約後の権利・日割り・無料体験・自動更新の表示を明確にする。

| お迎え券1枚 | 今日の候補から1匹追加確定 | ¥160 |

### 4.4 課金が生じる瞬間

- **当日の選択画面**：お気に入りの猫が2匹以上出た → 追加で迎える。
- **事前準備**：もっと多くの猫に出会いたい → またたびを使う／買う。
- **毎日の習慣化**：継続して候補数を増やしたい → またたびパス。
- **図鑑の未所持**：特定の猫がほしい → 指名・救済アイテム（導入する場合）。
- **特殊日・複合条件**：欲しい猫が一日に複数出た → 複数お迎え。

#### 体験上の原則

- 無料1匹の獲得を完了させてから、任意で追加お迎えを提案。
- 強制ポップアップや意図的な極端な重複を避ける。
- 無料で全種類に出会える道を基本的に残す。特殊な「世界唯一の旅猫」は訪問権と通常所有権を区別。
- 取り逃し救済の期間と条件を明確にし、購入を急がせすぎない。

## 5. 猫の出現条件：全ユーザー共通ルール

### 5.1 スマホの状態
- バッテリー残量 1% / 10% / 20% / 50% / 100%
- 充電中、充電開始、満充電
- 低電力モード（取得可能性・仕様を要検証）

### 5.2 歩数と日常
- 500 / 1,000 / 10,000歩達成
- 222 / 777 / 2,222歩などの特徴的な数値
- 歩数を累積して達成した記念日
- 一定期間アプリを開かず久々に復帰（7日、30日、100日など）
- ログイン頻度や連続起動。ただし継続強要ではなく、休んでも楽しい設計を優先。

### 5.3 曜日・暦・特殊日
- 金曜日、月末の金曜日
- **13日の金曜日**
- 猫の日：2月22日
- **閏日：2月29日**
- エイプリルフール：4月1日
- 七夕：7月7日
- ゾロ目：11月11日
- 年末年始：12月31日、1月1日
- クリスマス：12月25日
- 毎月29日：ゲーム独自の「肉球の日」
- 回文になる日付、年・月・日が特徴的に並ぶ日
- 春分・秋分、夏至・冬至
- 誕生日（自己申告の扱い、個人情報に注意）

### 5.4 月・天文・天候
- 満月、新月、上弦・下弦
- ブルームーン（定義を事前固定）
- 日食・月食、流星群など
- 雨、晴れ、雪、初雪、気温など
- 地域差がある天候・天文条件の判定地点と時刻を仕様化する。

### 5.5 コレクション条件
- 特定猫2〜3種類を所持する
- 同じ猫を3匹または5匹所有する
- 所有種類数が10 / 50 / 100匹に到達する
- 特定の猫を同じ部屋に配置する
- 特定の猫の訪問が複数回起こる

### 5.6 複合・隠し条件

例：
- 金曜日 × 雨 × 夜 = まよなか猫
- 満月 × 50種所有 = 王様猫
- 残量22% × 2,222歩 = 特殊数字猫
- 13日の金曜日 × 満月 = 幻の黒猫

条件は全員共通に保ち、図鑑のシルエットとヒント、発見者の報告で解明可能にする。検出が困難・不健康な行動を促す条件には注意し、後日入手手段を設ける。

## 6. 世界を旅する猫：看板機能

### 6.1 基本仕様

- **世界に1匹だけの特別な旅猫**が世界のユーザーのもとを移動する。
- 訪問された人は一定期間、その猫と触れ合い、写真撮影できる。
- 旅立った後も「訪問済み記録」「旅行記の一部」「記念写真」が残る。
- 旅行履歴：訪れた国、都市（公開同意と粒度に注意）、訪問人数、訪問日、通算旅行日数等。
- 過去訪問先のユーザーも次の訪問先を追いかけられる。SNSで行方の考察・報告が生まれる。
- 看板の世界唯一猫に加え、地域別・大陸別の旅猫を複数走らせる案もある。

### 6.2 旅の進行（未決定）
- 自動抽選で次の訪問者を決める／現在の訪問者が次の国を選ぶ／猫自身がランダムで決める、など。
- 初期はユーザーのいる国だけを対象とし、利用国拡大に合わせて旅の範囲を拡張。
- 滞在期間、抽選資格、訪問済み再抽選、アクティブユーザー優先などの公平性を設計する。
- **唯一猫はショップで直接販売しない**。代わりに思い出と参加体験が価値。

### 6.3 旅行記とユーザーの痕跡
- 猫を迎えたユーザーが定型メッセージまたはスタンプを1つ残す。
- 世界中のユーザーによる旅行記が積み重なる。
- 自由文はモデレーション負荷が高いため、初期は定型文を推奨。
- 個人を特定できる住所・座標・細かな移動履歴は公開しない。位置の公開可否と表示粒度は本人の選択にする。

## 7. 世界全体の共同目標と報酬

**ユーザーの参加国が増えるほど、世界全員に猫が届く仕組み**を看板の一つにする。

例：
- 新しい国から最初のユーザーが参加 → 「あなたは韓国で最初のユーザーです」（事実確認後のみ表示）。
- それによって利用国数30か国到達 → 世界全員に記念猫が訪れる。
- 達成した国・任意公開の貢献者を記念ページに残す。

| 達成条件 | 報酬・記録例 |
|---|---|
| 利用国数10 / 30 / 100か国 | せかい猫 / たびびと猫 / ちきゅう猫 |
| 世界全体の累計歩数1億歩 | マラソン猫 |
| 世界全体の猫ジャンプ100万回 | ぴょんぴょん猫 |
| 世界全体の猫獲得100万匹 | おまつり猫 |
| 世界全体の記念撮影100万枚 | カメラマン猫 |
| 旅猫が新たな国へ初訪問 | 当該国の訪問記念猫 |
| 世界で初めてある猫の条件を解明 | 第一発見者称号・共通出現の開放 |

- 一部のイベントは達成時に全員へ配布、または数日間全員の候補に確定出現。
- 不正な登録数・歩数・写真連打などへの対策を設計する。
- 参加国の判定・本人同意・地域情報の公開範囲に慎重な設計が必要。

## 8. 撮影機能

### 8.1 カメラ合成（初期版候補）
- スマホカメラを起動し、ライブ映像の上に猫モビーを表示。
- 位置移動・拡大縮小・回転、簡易影、写真撮影、画像保存・共有。
- 旅猫と写真撮影可能。日時・国（同意時）・直前に訪れた国などを記念カードに表示。
- 2D透過PNG主体で実装できるため、初期版に適する。

### 8.2 AR撮影（発展版）
- 床・机に猫を配置し、カメラ移動に追従する体験。
- 本格的な立体回り込みには複数角度画像や3Dモデルが必要。
- まず2D合成で利用率・SNS共有率を検証してから導入判断。

### 8.3 SNS向け出力
- 猫の発見カード：猫名、出会い日、出現条件のヒント、レア度。
- 旅猫記念カード：前にいた国 → 自分の国、旅行日数、訪問国数。
- 9:16縦長動画、画像の保存・共有機能。
- 正確な住所やGPS座標、不要な画像位置メタデータを埋め込まない。

## 9. 友達・SNSによる拡散

- 発見条件は全員共通なので、他人の攻略投稿が役に立つ。
- 珍しい日付や世界イベントに発見投稿が集中する。
- 世界を旅する猫の現在地・行く末が話題になる。
- 初期相棒猫の差異や猫の特殊行動で比較・動画化が可能。
- 友達の猫が訪問したり、重複猫を交換できる仕組みは将来拡張。
- SNS共有は任意。共有しなければ収集上不利になる仕組みは避ける。

## 10. 画面構成案

### タブ候補
1. **ホーム／猫部屋**：所有猫が暮らす。数匹がゆるく動く。タップ反応あり。
2. **図鑑**：猫種、所持数、未所持シルエット、出現ヒント、希少性、出会い履歴。
3. **今日の出会い**：当日の候補3〜6匹、無料1匹選択、お迎え券で追加獲得、またたび導線。
4. **ショップ**：お迎え券、またたび、月額パス、装飾品等。

### 補助画面
- **世界**：旅猫の地図・旅行記・全世界共通目標・記念碑。
- **撮影**：所有猫または旅猫のカメラ合成・写真保存。
- **出会い履歴**：選ばなかった候補の記録と、救済入手可能な場合の導線。
- **通知・設定**：時刻、通知、地域設定、権限、プライバシー。

## 11. iOS実装に関する前提と注意

- 歩数：Core Motion / HealthKit等の利用可能なデータ源、権限、端末対応を検討。バックグラウンドでの厳密なリアルタイム判定を前提にしない。
- バッテリー：アプリが取得できた時点の情報を判定に利用。バックグラウンド・強制終了中の充電イベントを保証しない。
- 天気：天候データと必要に応じた地域情報が必要。位置利用の同意と代替地域選択を設計。
- 天文：月齢・日食などの計算定義、対象地域、タイムゾーンを明確化。
- 定時通知：ローカル通知またはサーバープッシュ。OSの許可・配信状況に依存するので、通知は補助。サーバー内の出会い確定時刻と混同しない。
- 共通条件：**ルール定義は共通**。現地天候や現地時刻によって実際の該当ユーザー・日が違うことは許容。
- アプリを閉じている間も猫の出会いは進行し、次回起動時にサーバー／記録から復元。
- 世界を旅する猫、国数達成、所持情報、購入権利、交換にはバックエンドが実質必要。
- 不正対策：端末時刻改ざん、歩数改ざん、複数アカウント、課金復元、イベントの重複付与を考慮。
- ランダム性を含む有料購入は、適用されるApp Storeルールに基づき確率を購入前に表示する。
- 個人データ・位置情報・通知に関してはApp Store審査・法令に沿って実装。

## 12. 初期版（MVP）提案

**収集と課金の検証を最優先**する。世界機能は段階的に導入。

### MVP必須
- 猫モビー一覧（初期数は制作工数と相談）
- 日次20:00の候補3匹確定、無料1匹選択
- お迎え券による候補の追加獲得
- またたびによる候補数増加
- 図鑑・所持・重複・出会い履歴
- 日付・曜日・所持猫数など、技術的に容易な共通出現条件
- 通知と通知なしでの受け取り
- アプリ内課金の付与・復元・検証

### 次段階
- 歩数・バッテリー・月齢・天気条件
- またたびパス
- 世界の旅猫と旅行記
- 世界全体の共同目標と国数達成
- カメラ合成とSNSカード
- 猫交換・友達訪問
- ARと高度なアニメーション

旅猫が製品の差別化の中核なら、MVPのベータ段階で最低限の「世界を旅する1匹と履歴」を早期に検証する別案もある。

## 13. 主要指標（KPI）
