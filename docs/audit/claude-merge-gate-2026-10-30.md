## A：マージ前に直す

### A-1（要判断）：匿名のパス加入者が新しい iPhone で復元できず、請求だけ続く
- 場所：`app/src/services/account/purchase.ts:165-170`、`app/src/services/account/credentials.ts:11`、`server/src/worker.ts:368`
- 起きること：鍵は `THIS_DEVICE_ONLY` なので、iCloud バックアップやクイックスタートでは新しい端末に移らない。引継ぎコードを発行せずに端末を失った匿名加入者は、Apple が有効なパスを返しても、アカウントが無いため `otherAccount` になり、「別の記録と結びついています」と出る。Apple の請求は続く。
- さらに、パスを買い直そうとしても Apple は既存の取引を返す。その `appAccountToken` は古いアカウントなので 403 になり、画面は「開き直すと自動でやり直します」と出すが、成功することはない。
- 影響：ガイドライン 3.1.1 は、復元できる購入に復元の手段を求めている。同じ端末の入れ直しは Keychain が残るので動くため、審査では見えにくく、公開後の問い合わせと返金として表に出る。
- 背景：購入の証明だけでアカウント全体を引き継ぐ方式は、再利用できる証明で鍵を奪えるため、運営者の指定で廃止した。この判断は正しい。問題は、アカウントごとの引継ぎと、パスの権利を分けていないこと。
- 案：期限内のサブスクの署名つき取引を出した場合は、**パスの権利だけ**を新しいアカウントへ移す（残高と鍵は動かさない）。証明が漏れても、失うのは期限内のパスの権利だけ。毎月のお迎え券の扱いは、運営者が決める。

### A-2：案内どおりに操作すると、買ったばかりの残高が消える
- 場所：`app/src/core/account.tsx:279`、`app/src/features/shop/ShopScreen.tsx:87-88`、`app/src/features/settings/SettingsScreen.tsx:391`
- 起きること：Apple 連携済みの人が新しい端末で、先に匿名のまま購入する。購入後の案内で Apple サインインを押すと `in_use` になり、「設定の『アカウント』から、その記録を引き継いでください」と出る。従うと `restoreWithApple` が鍵を置き換え、購入した匿名アカウントの鍵は端末から消える。残高は孤立し、利用者には戻せない。確認の文面にも、この損失は書かれていない。
- 直し方：端末のアカウントに有料の残高かパスがあるときは、置き換えを止める（または損失を明記して同意を取り、先に引継ぎ先へ移す方法を用意する）。

### A-3：使っていないバックグラウンド音声の宣言で、審査に落ちるおそれ
- 場所：`app/app.json` の `"expo-audio"`
- 起きること：`expo-audio` のプラグインは `enableBackgroundPlayback` の既定が true で、`UIBackgroundModes: audio` を Info.plist に足す（`withAudio.js:22-34` で確認）。アプリは `shouldPlayInBackground: false`（`services/audio.ts:184`）で、裏で音を出さない。使わない宣言は、ガイドライン 2.5.4 の典型的な却下理由。
- あわせて `NSMicrophoneUsageDescription` に英語の既定文が入る。カメラは `microphonePermission: false` にしてあるのに、こちらは未指定。
- 直し方：`["expo-audio", { "enableBackgroundPlayback": false, "microphonePermission": false }]`。マイクの説明文を外したことで、アップロード時に ITMS-90683 が出たら、日本語の説明文に替える。

## B：公開前に直す

### B-1：買った分を使っても、画面の残高が減らない
- 場所：`app/src/core/game.tsx:524-529`、`app/src/core/account.tsx:244`、`app/src/core/spending.ts:66-70`
- 起きること：`setPaid` は React の更新として積まれるが、そのあと `runSpend` が古い `stateRef` から作った状態を、値そのままで `setState` する。後の値が勝つので、残高の写しは使う前の数に戻る。次の `refresh` まで直らない（ショップを開く、60秒以上たって復帰、30分ごと）。残高が尽きても数が残って見え、押すと「通信できなかったか、足りません」と出る。
- お金は失われない。購入者にはすぐ見える。確かさ：コード読解で確認。実機は未確認。

### B-2：未解決の消費と 401 が重なると、アカウント操作がすべて止まる
- 場所：`app/src/services/account/purchase.ts:192`、`app/src/core/game.tsx:601-604`
- 起きること：`spendPaid` は 401 を `offline` として扱うので、`pendingSpend` が消えない。`withAccountChange` は `pendingSpend` があると実行しないため、別の端末へ引き継いだ前の端末などで、Apple サインインのやり直し、「新しく始める」、購入の復元、**アカウント削除**が、どれも失敗する。アプリを入れ直すまで解けない。
- 直し方：401 は別の結果として返し、鍵が失効した消費の確認は打ち切れるようにする。

## 確認して問題がなかったもの

- **確率の説明**：`buildDay` は条件を満たした猫を均等にシャッフルして 6 匹に絞る。重みづけなし。購入やまたたびで候補は変わらない。候補の抽選に `Math.random` は使っていない。ショップ・審査メモ・掲載文の説明は、実装と一致する。
- **購入の検証**：`x5c` の3段の鎖、ルートの一致、App Store の OID、バンドル ID、環境、`appAccountToken` の一致。
- **二重付与**：取引番号で一度だけ。返金が先に届いても付与しない。消費は `requestId` で一度だけ。残高は負にならない。
- **認証**：鍵はハッシュで保存し、比較は固定時間。引継ぎコードは 256 ビットの使い捨てで、ハッシュのみ保存。
- **削除**：Apple のトークンを取り消してから削除する。パスが自動解約されないことを、画面と `/legal` に明記している。
- **ガイドライン 3.1.2**：パスの価格・期間・自動更新・解約方法、EULA とプライバシーポリシーへのリンクが、購入の画面にある。
- **開発用の入口**：`__DEV__` の中。世界の機能は `WORLD_ON = false`。
- **本番**：`/health` `/time` `/privacy` `/support` `/legal` が応答する。`/auth/recover-with-code` は応答した（既に反映済み。デプロイは 19:27、コミットの約1分後）。Apple の鍵のシークレット3つは登録済み。主なテーブルと `users` の列は揃っている。
