## A：ビルド・審査の前に

### A1. 購入画面に、利用規約（EULA）とプライバシーポリシーへのリンクが無い
- 場所：`app/src/features/shop/ShopScreen.tsx`（ショップ全体。リンクは設定画面にしかない）
- 何が起きるか：自動更新サブスク（またたびパス）は、ガイドライン 3.1.2 で、**アプリ内の購入の流れの中に**、利用規約とプライバシーポリシーへの動くリンクが求められる。無いと、ほぼ確実に指摘される。
- 直し方：ショップの下（またたびパスの説明の近く）に「利用規約」「プライバシーポリシー」のリンクを置く。利用規約は、Apple 標準の EULA（`https://www.apple.com/legal/internet-services/itunes/dev/stdeula/`）か、自前の規約ページ。プライバシーは `/privacy`。

### A2. 世界タブが「サンプル表示（サーバー未接続）」
- 場所：`app/src/features/world/WorldScreen.tsx:8, 21, 29, 50, 151`。チュートリアルの最後の段も「今はサンプル表示です」（`features/tutorial/steps.ts:67`）。
- 何が起きるか：ガイドライン 2.1（未完成のアプリ）と 2.3（実際の内容と違う表示）で、サンプルやダミーのデータ（「フランス限定モビー配布中！」などの架空のお知らせ）は、リジェクトの典型。
- 直し方：1.0 では世界タブを外す（下のナビを3つにする）か、実データだけを見せる形にする。チュートリアルの「世界」の段も外す。

### A3. 購入の前に、Apple でのサインインを必須にしている
- 場所：`app/src/services/account/purchase.ts:78`（`apple_needed`）、`ShopScreen.tsx` の確認ダイアログ。
- 何が起きるか：ガイドライン 5.1.1 は、アカウントに結びつかないアプリ内課金（消耗型）を、登録（サインイン）なしで買えるようにすることを求めている。「購入するには、Apple でのサインインが必要です」は、指摘を受けやすい。メールや名前を受け取らない Sign in with Apple でも、「購入の前の登録」とみなされうる。
- 直し方：匿名のアカウントのまま買えるようにする（サーバーは `appAccountToken` で匿名のアカウントに結びつけられるので、そのまま動く）。Apple サインインは「機種変更で引き継ぐため」の任意の案内にする。サブスクの購入の復元は、App Store の「購入を復元」で足りる。
- 判断が要る：運営として「必ず引き継げる」ことを優先するなら、今のままで審査に出し、指摘されたら直す手もある。ただ、審査が1往復増える。

### A4. `expo-asset` が入っていない
- 場所：`app/package.json`。`npx expo-doctor` の結果「Missing peer dependency: expo-asset（Required by: expo-audio）。Expo Go 以外では、アプリが落ちることがある」。
- 直し方：`npx expo install expo-asset`。

### A5. iPad に対応する設定になっている（`supportsTablet: true`）
- 場所：`app/app.json:10`
- 何が起きるか：iPad 用のスクリーンショット（13インチ）が審査の提出に必須になり、iPad での表示も審査される。アプリは横幅 430pt で中央に表示するので、iPad では細長い画面になる。
- 直し方：iPhone 専用で出すなら `false` にする（iPad でも、iPhone アプリとして動く）。iPad を正式に対応するなら、iPad のスクリーンショットを用意する。ビルドに入る設定なので、**ビルドの前に決める**。

### A6. 小さい画面（iPhone SE：375×667pt）で、ホームの下が、ナビに隠れる
- 場所：`app/src/features/home/HomeScreen.tsx`（下の予告カードとさつえいボタン）と `App.tsx`（下のナビ）。
- 何が起きるか：Web で 375×667 にして確認した。開いた直後は、予告カードとさつえいボタンが、下のナビの裏に重なる。スクロールすれば出てくる（最初に「スクロールしても出ない」と書いたのは誤り。測り直して訂正した）。390×844 以上の画面では起きない。
- 直し方：ScrollView の下の余白を、ナビの高さ（`tabH`）＋ safe area にする。実機（SE）でも確認する。

## B：公開前に直したい

### B1. 毎日20時の通知が、初期状態でオフのまま、どこからも案内されない
- 場所：通知を有効にするのは設定画面だけ（`features/settings/SettingsScreen.tsx:80`）。`notifyEnabled` の初期値は `false`（`core/game.tsx:98`）。相棒選びでは、歩数と位置の許可だけを求めている（`features/onboarding/OnboardingScreen.tsx:135`）。
- 何が起きるか：アプリの中心の「毎晩20時に出会いが届く」の通知が、設定を開いた人にしか届かない。チュートリアルや「ようこそ」のお知らせは、通知が届く前提の文面になっている。
- 直し方：相棒を選んだあと、またはチュートリアルの最後に、理由を説明してから通知の許可を求める。

### B2. 公開後に、サーバーの `PURCHASE_ENVIRONMENTS` から Sandbox を外す手順は、やめたほうがよい
- 場所：`docs/release-checklist.md` の H-3、`server/wrangler.toml` のコメント。
- 何が起きるか：アップデートの審査でも、Apple の審査員はサンドボックスで購入を試す。Sandbox を外すと、次のバージョンの審査で購入が失敗し、リジェクトされる。サンドボックスの購入ができるのは、開発者が作ったテスターと、TestFlight・審査だけで、一般の利用者は作れない。
- 直し方：`Production,Sandbox` のまま運用する。サンドボックスの購入は `purchases.environment` に記録されているので、売上の集計では除く。手順書と `wrangler.toml` のコメントを直す。

### B3. Expo SDK のパッチ版が古い（11個）
- 場所：`app/package.json`。`expo` 58.0.19（期待 58.0.21）、`react-native` 0.88.0（0.88.1）、`expo-camera`、`expo-notifications` ほか。
- 直し方：`npx expo install --check` で、そろえる。ビルドの前にやっておくと、ネイティブの不具合を避けやすい。

### B4. 使っていない画像が、約 17MB アプリに入る
- 場所：`app/src/ui/uiAssets.ts` は、`app/assets/ui` の全画像を `require` しているので、使っていない画像もすべてアプリに入る。コードから参照されていない画像は 60 個、約 16.9MB（`bg/screen-shop` 2.7MB、`share/*-story` 各 1MB 前後、`login/month-frame` 0.9MB、`share/watermark` など。`brand/app-icon` は `app.json` が使うので除く）。
- 直し方：使わない画像を消すか、`uiAssets.ts` を、使う画像だけを登録するように変える。

### B5. 位置情報の許可文が、外部へ送ることに触れていない
- 場所：`app/app.json` の `locationWhenInUsePermission`「…おおまかな位置だけを使い、保存はしません。」
- 何が起きるか：実際は、約10kmに丸めた位置を、天気予報サービス（MET Norway）へ送る。ポリシーには書いてあるが、許可文が「使うだけ」と読める。
- 直し方：「その日の天気を調べるため、おおまかな位置を天気予報サービスに送ります。保存はしません。」のように書く。
