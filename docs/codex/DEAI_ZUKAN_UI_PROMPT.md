# Codex 依頼プロンプト（出会い画面とコレクション画面を、参考画像のUIに作り直す）

「出会い」と「コレクション」の2つの画面を、参考画像（`docs/codex/reference/deai-zukan-ui.webp`。左が出会い、右がコレクション）のUIに作り直す。**素材（画像アセット）の作成と、コードの修正の両方を、あなた（Codex）が行う。**

ブランチ `codex/deai-zukan-ui`（`feature/home-roll-anim` から分岐。作成済み。ホームの背景の切り替えと、背景を画面の端まで敷く `Backdrop` の `bleed` が入っている版）。**worktree はあなた（Codex）が作る**。作業フォルダは **`D:\mobby-cat\.worktrees\deai-zukan-ui`**。

```bash
git -C D:/mobby-cat worktree add D:/mobby-cat/.worktrees/deai-zukan-ui codex/deai-zukan-ui
```

そのフォルダの中だけで作業し、`D:\mobby-cat` 本体や他のブランチ・worktree は触らず、ブランチも切り替えない。ビルド（`eas build`・`expo run:*`）はしない。

## 最重要ルール（これを破らない）

1. **見た目はすべて、画像アセットで作る。コードで見た目を描かない。**
   - `View` / `StyleSheet` で、色・背景色・角丸・枠線・影・グラデーション・飾りを描くことを**禁止**する（`backgroundColor`、`borderRadius`、`borderWidth`、`shadow*`、`elevation`、`LinearGradient` などで見た目を作らない）。
   - 板・看板・カード・ボタン・バー・チップ・ゲージ・吹き出し・アイコン・背景・飾りは、必ず画像（`Pic` / `Slice`（9スライス）/ `Backdrop` / `ImgButton` / `Card` など、既存の部品経由）で出す。
   - コードで描いてよいのは、**中身が変わるもの**だけ：文字（`T`）、数字、ゲージの長さ（既存の `Gauge`）、画像の位置・大きさ・並び（レイアウト）。
   - 必要な素材が足りないときは、**コードで代用せず、素材を作る**。
2. **素材は、参考画像を基に作る。** 参考画像の絵柄（和の屋台・格子・提灯・桜・木の板・和紙のカード・やわらかい金のふち・暖色のあかり）を、既存のビジュアルルールのまま、各部品の素材として作り起こす。参考画像そのものを切り抜いて使わない（解像度が足りず、文字も入っているため）。built-in image_gen で、参考画像と既存素材を見本に生成する。
3. **文字は焼き込まない**（次の例外だけ）：2つの見出し看板（「出会い／今日のにゃこモビー」「コレクション／にゃこモビー図鑑」）は、既存の `brand/title-collection` などと同じ扱いで、文字入りの画像にしてよい。ほかの文字（猫の名前・数字・時刻・「所持中」などのラベル）は、すべてコードの文字（`T`）で重ねる。
4. **中身（ゲームの動き）は変えない。** 出会い（候補・えらぶ・ひらく・お迎え・昨日の子・権限の案内）とコレクション（検索・絞り込み・お気に入り・詳細）の機能は、いまのまま動くこと。見た目だけを作り直す。参考画像にあって、いまのアプリに対応する機能がないもの（下の「作らないもの」）は作らない。

守るべき既存のルール：`docs/codex/CODEX_PROMPT.md` の「ビジュアルルール」、`app/assets/ui/manifest.json` の記録の形式（`prompt` / `method` / `processing` / `slice` / `sha256` / `bytes`）、`assets/ui-records/provenance/` への理由と作り方の記録、素材は @3x（1pt = 3px）、透過PNG、既存素材と同じふち・影・ふくらみ。

## 参考画像の読み取り

画面は iPhone 幅（幅 360〜440pt）。上から下へ。共通の部品（ヘッダー：通貨のピル・ベル・設定、下のタブ）は位置はいまのままで、絵柄を新しい世界観にそろえる。

### 出会い（左）

- 背景：夕暮れの和の屋台の中。木の梁・提灯（左右の柱に）・桜の枝（左上）・肉球の入ったのれん（上の段）・木のカウンター・板の床。看板や袋は含めない（別素材）。
- 見出しの看板：木の看板「出会い ─ 今日のにゃこモビー ─」（肉球のアイコン付き）。
- 説明の板：屋根の付いた木の板。カレンダーの絵と「今日の出会いは 今夜20:00に届くよ」、砂時計の絵と「あと 03:42:18」。
- 相棒の猫：カウンターの上から顔と前足を出している（いまの相棒の猫の画像を、カウンターの手前の板の後ろに置いて、体の下が隠れるようにする）。
- 袋が3つ：和柄（桜）の袋に、肉球の札。まだひらいていない候補を表す。
- 吹き出し：クリーム色の丸い吹き出し（しっぽが**上**向き）に「どの子に会えるかな… 少しだけ、気配がしてるよ。」
- 「今日の出会いの気配」の板：木のふちの和紙の板。見出し行と、3行（肉球／もみじ／きらきらの絵＋文）。
- 下のタブ：丸みのある四角のボタン3つ（ホーム・出会い・コレクション）。選んでいるものはオレンジで光る。

### コレクション（右）

- 背景：和の店の中。提灯・木の棚・観葉植物・格子窓。床は木の板。見出しや一覧は別素材。
- 見出しの看板：弧を描く木の看板「コレクション ─ にゃこモビー図鑑 ─」。上で猫が寝ている。右上の隅に、招き猫の飾り（見出しの看板とは別の素材）。
- 達成率のカード：和紙のカード。左に月桂樹、「図鑑達成率」と大きい「251 /251」、オレンジのゲージ、右に猫と「コンプリート！」のリボン（リボンは、全部そろったときだけ出す。そろっていないときは出さない）。
- 検索：横長の検索欄（虫めがねの絵）。
- 絞り込み：丸い角のチップが横に並ぶ。「すべて」（選択中はオレンジ）「所持中」「未所持」「レア」（きらきらの絵）「お気に入り」（星の絵）。
- 一覧：4列。和紙のカード1枚ごとに、猫の絵・右上のハート・「No.001」・名前。
- 一覧の下の木のバー：「並び順：図鑑順 ▼」のボタン（左）、「251 体のにゃこモビー」、並べ方の切り替えのボタン（右）。

## 作らないもの（いまのアプリに対応する機能がない）

- コレクションの「図鑑／暮らし」のタブ（「暮らし」の機能がない）と、検索の右の絞り込みのボタン（チップで足りている）。**コードにも出さない**。見出しの下は、達成率のカード → 検索欄 → チップ、の順にする。
- 出会いの「今日の出会いの気配」の板は、いま出している情報（候補の構成・珍しい猫の気配・歩数や位置情報の案内）を、この板の形に収める。新しい種類の情報を作らない。表示する情報が1つもないときは、板ごと出さない。

## 画面の作り直し（コード）

`app/src/features/deai/DeaiScreen.tsx`、`app/src/features/zukan/ZukanScreen.tsx`、`app/src/ui/kit.tsx` の部品、タブバー。次を守る。

- 背景は `Backdrop`（`bleed` 付き。画面が広くても端まで敷く）。中身は今までどおり、幅の上限 `MAX_W`（`app/src/ui/layout.ts`）の列の中。
- 余白は、タブバーの高さ（`useTabPad`）と画面の安全領域を守り、スクロールする場所（出会いの候補、コレクションの一覧）は今までどおりスクロールする。見出しとヘッダーは固定。
- 画面の幅 360〜440pt、高さ 640〜960pt で、重ならない・切れないこと。小さい端末では、飾り（招き猫、桜）を小さくするか隠す。
- 出会いの状態は全部、同じ絵柄にする：最初の夜を待つ画面（参考画像）／候補が出ている画面（候補を和紙のカードに、ひらいていない候補は袋で出す。選んでいる候補は `fukuro-picked`）／候補がない画面／昨日の子／権限の案内／お迎えの演出（`RevealOverlay` などで使っている、ひらく前の絵は、袋の素材に合わせて差し替える）。
- チュートリアルの `TourAnchor`（`tabbar` など）と、各ボタンのアクセシビリティの名前・読み上げは、今までどおり。
- 絞り込みのチップは、参考画像の並び（すべて／所持中／未所持／レア／お気に入り）にする。「レア」は、いまのレア（`rarity` 3 以上）と同じ意味。「未所持」を新しく足す（持っていない子だけ。シルエットで出る）。
- 並び順のボタンと、並べ方の切り替えは、**実際に動くもの**にする：並び順は「図鑑順（既定）」「レア度順」「名前順」を、押すたびに順に切り替える（バーの文字も変わる）。並べ方は、4列と3列の切り替え。**動かないボタンを置かない。**
- 一覧のカードのハートは、お気に入りの切り替えと同じ状態を見せる（押せば切り替わる。いまの詳細のハートと同じ処理）。
- いまの猫の絵・名前の長いときの2行・「所持中」「No.」の表示ルールは、そのまま。
